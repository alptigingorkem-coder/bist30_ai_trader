### 1. Risk Yönetimi (Tightening)
Max Drawdown'ı düşürmek ve sermayeyi korumak için köklü değişiklikler yapıldı:
- **Stop-Loss ATR Çarpanı:** `3.0` → `2.0` olarak güncellendi. Zararlı pozisyonlar daha hızlı kapatılıyor.
- **Trailing Stop:** Aktif, çarpan `2.0`. Kâr koruma mekanizması hassaslaştırıldı.
- **Devre Kesici (Circuit Breaker):** Portföy değeri zirveden %25 düşerse tüm işlemler durdurulup nakite geçme kuralı `config.py` içine eklendi (`MAX_DRAWDOWN_LIMIT = 0.25`).

### 3. Hiperparametre Optimizasyonu (Optuna)

## 🐳 Faz 4: Altyapı Modernizasyonu (Docker + TimescaleDB + GPU)

### 4.1 Docker Konteynerizasyon

Proje çok servisli bir Docker mimarisine taşındı:

**Dosya: `Dockerfile`**
- Python 3.12-slim tabanlı imaj.
- ROCm 6.2 uyumlu PyTorch (`--index-url https://download.pytorch.org/whl/rocm6.2`) ile explicit GPU desteği.
- Tüm Python bağımlılıkları (`requirements.txt`) dahil.

**Dosya: `docker-compose.yml`**
4 adet servis tanımlandı:

| Servis | İmaj | Port | Görev |
|--------|-------|------|-------|
| `timescaledb` | `timescale/timescaledb:latest-pg14` | 5432 | Zaman serisi veritabanı |
| `app` | Custom (Dockerfile) | — | Arka plan işçisi (Paper Trading Runner) |
| `api` | Custom (Dockerfile) | 8000 | FastAPI REST/WebSocket Backend |
| `ui` | Custom (`ui/Dockerfile`) | 3000 | Next.js Frontend Dashboard |

**GPU Passthrough (AMD ROCm):**
```yaml
# docker-compose.yml - app service
devices:
  - /dev/kfd:/dev/kfd
  - /dev/dri:/dev/dri
group_add:
  - "44"   # video grubu (GID)
  - "992"  # render grubu (GID)
environment:
  - HSA_OVERRIDE_GFX_VERSION=10.3.0
  - CUDA_VISIBLE_DEVICES=0
```

> **Kritik Not:** Grup adları (`video`, `render`) konteyner içinde çözülememekteydi. Çözüm: sayısal GID (`44`, `992`) kullanılması.

### 4.2 TimescaleDB Entegrasyonu

**Dosya: `utils/db_manager.py`**
- `psycopg2.pool.SimpleConnectionPool` ile bağlantı havuzu yönetimi.
- Otomatik şema oluşturma: `market_data`, `fundamental_data`, `trades` tabloları.
- TimescaleDB `hypertable` dönüşümü (zaman serisi sorgularında yüksek performans).
- `UPSERT` ile çakışma yönetimi (`ON CONFLICT DO NOTHING`).

**Dosya: `scripts/migrate_to_db.py`**
- Mevcut CSV/Parquet verilerini TimescaleDB'ye toplu aktaran migrasyon scripti.

**Dosya: `utils/data_loader.py` (Güncelleme)**
- DB-First stratejisi: Önce veritabanından oku, yoksa Yahoo Finance / İş Yatırım'dan çek.
- SSL sertifika bypass (`data_loader.py` içinde `verify=False`) ile İş Yatırım fallback'i güvence altına alındı.

## 🌐 Faz 5: Modern Web Arayüzü & API

### 5.1 FastAPI Backend

**Dosya: `api.py`** (Yeni oluşturuldu)

```
Mimari: FastAPI + uvicorn (auto-reload)
```

| Endpoint | Tür | Açıklama |
|----------|-----|----------|
| `GET /` | REST | Sağlık kontrolü (`{"status": "ok"}`) |
| `GET /api/market-data/{symbol}?limit=N` | REST | TimescaleDB'den OHLCV tarihsel veri |
| `GET /api/portfolio` | REST | Portföy durumu (nakit, pozisyonlar) |
| `WS /ws` | WebSocket | Gerçek zamanlı piyasa güncellemeleri & ping/pong |

**Teknik Detaylar:**
- CORS `allow_origins=["*"]` ile tüm domain'lere açık (geliştirme modu).
- `ConnectionManager` sınıfı ile aktif WebSocket bağlantıları yönetiliyor.
- Veritabanı sorguları `psycopg2` raw cursor ile yapılıyor (Pandas overhead'ı atlandı).
- Arka plan görevi (`mock_market_update`) `asyncio.create_task` ile başlatılıyor; ileri sürümde Redis Stream/Queue ile değiştirilecek.

**Bağımlılık Eklentileri (`requirements.txt`):**
```
fastapi>=0.104.0
uvicorn[standard]>=0.24.0
websockets>=12.0
```
